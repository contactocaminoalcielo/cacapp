# Instalado como /etc/cron.d/orbit-backend (root, 0644).
#
# EL RELOJ (leer antes de tocar una hora)
# --------------------------------------
# cron hereda la zona del SISTEMA, no UTC. Hasta el 2026-07-16 el VPS estaba en
# Europe/Berlin y esta cabecera afirmaba "el cron corre en UTC": era FALSO. Todo
# corria 2h antes de lo escrito (el job de las "15:00 UTC" salia 13:00 UTC =
# 08:00 Bogota) y en octubre Berlin pasa a CET y se habria corrido otra hora mas,
# solo, sin que nadie tocara nada.
#
# El host se paso a America/Bogota, que NO tiene horario de verano:
#   → las horas de abajo SON hora de Bogota y no se desvian nunca.
#
# CRON_TZ no es opcion: este cron (3.0pl1-137) no lo soporta — no existe ni la
# cadena en el binario (`strings /usr/sbin/cron | grep -i tz` → vacio).
# Si alguien devuelve el host a otra zona, ESTO se rompe en silencio: ningun job
# falla, solo ocurren a deshora y nadie se entera.
#
# --max-time 300: sin el, un backend colgado deja el curl esperando PARA SIEMPRE
# y el job del dia se pierde mudo (paso el 2026-07-16).
#
# Cada job decide si aplica (dias_planificacion, dias habiles, festivos). Todos
# idempotentes: correrlos dos veces el mismo dia no duplica nada.

# Jobs Tenjo — propuesta de lote (solo actua lun/mie/vie; lo decide el job) y alertas.
0 6 * * * root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/generar-propuesta >> /var/log/orbit-backend-cron.log 2>&1
30 6 * * * root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/alertas >> /var/log/orbit-backend-cron.log 2>&1

# Reportes Grupales (Fase 5) — sincroniza reportes, marca vencidos y genera alertas.
45 6 * * * root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/grupales >> /var/log/orbit-backend-cron.log 2>&1

# Solicitud de imagenes — prepara los contactos del dia (NO envia; una persona valida).
# 07:00: la bandeja queda lista al comenzar la jornada. Recupera vencidos no procesados.
0 7 * * * root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/contactos-imagenes >> /var/log/orbit-backend-cron.log 2>&1

# Seguimiento de imagenes — 2o contacto (+3 dias habiles) y 3er contacto (+15) desde
# el envio del 1o; cierra SIN_RESPUESTA + alerta tras el 3o. SOLO dias habiles (L-V):
# el cron no conoce los festivos de Colombia, pero el job SI (fn_es_dia_habil), asi
# que en festivo simplemente no escribe a nadie.
# Idempotente: el indice unico (solicitud_id, numero) impide duplicar un contacto.
30 10 * * 1-5 root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/seguimiento-imagenes >> /var/log/orbit-backend-cron.log 2>&1

# Digitales — revisa cada 10 minutos, solo en horario diurno. El job aplica un
# corte de activacion y nunca toma los servicios historicos anteriores a este.
# Maximo 5 por corrida y bloqueo global para impedir dos ejecuciones simultaneas.
*/10 7-20 * * * root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/digitales >> /var/log/orbit-backend-cron.log 2>&1

# Afiliaciones pre-exequiales — marca VENCIDA (vencio el contrato vigente) y
# CANCELADA (paso la gracia). Idempotente. Instalado en prod 2026-07-16.
0 7 * * * root curl -s --max-time 300 -X POST -H "x-job-token: $(grep '^JOB_TOKEN=' /opt/orbit-backend/.env | cut -d= -f2-)" http://127.0.0.1:8787/jobs/afiliaciones >> /var/log/orbit-backend-cron.log 2>&1
